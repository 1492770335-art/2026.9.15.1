# one-hot 类别编码规格（onehot_spec.md）

## 目标
将 f83–f99（17 列离散类别，值 ∈ {0,1,2}）从「序数数值」替换为「17×3=51 维 one-hot」，去掉原有 17 个数值列。

## 编码定义（onehot17）
- 输入布局：`[f0..f82 (83 连续, 保留) | onehot(f83..f99) (17×3=51)]`，总 134 维。
- 对类别列 j（j=0..16，对应 f83+j）：值 v∈{0,1,2} → 在组内位置 `j*3+v` 置 1，其余 0。
  - v=0 → [1,0,0]；v=1 → [0,1,0]；v=2 → [0,0,1]。
- dtype float32；逐行（逐股票逐 tick）无状态，无跨股票/跨日串联。
- 未知/越界值：审计确认全数据 0 个越界（79.58M 单元 ∈ {0,1,2}），故无需工程回退；编码器仍带 `valid` 保护（越界组置全 0），仅供防御。

## 当前编码（审计结论）
- 现有 K16-GRU 网络 `nn.GRU(100, 128)` 将 f083–f099 作为数值 0/1/2 直接输入（序数、无 one-hot/无 embedding）→ 隐式线性有序约束是本次要替换的目标。

## 资源（GRU128，输入 100→134）
- 仅输入→隐层权重增长：3·128·(134−100) = **+13056 参数**；隐层→隐层、输出不变。
- 数据内存 134/100 = **1.34×**。
- 容量混淆：输入维数增加引入容量变化，若 K1 有增益，需等容量 placebo 排除。

## 训练端 / 流式端一致
- 离线 `build_onehot17(X_raw)`（全矩阵）与在线 `online_onehot17(x_t)`（单 tick）逐元素一致（单测 max abs diff = 0）。
- K16 左填充由 make_batch 在 134 维矩阵上零填充（编码器不涉及历史）；日初 reset 无状态；50 股票顺序逐行独立。
